SEARCH FAILURE ROOT CAUSE
- systems.timeEnergy installs the mature running-world clock.
- While speed > 0 and no modal is open, the world clock requests a full RF.UI.render about every 0.18 seconds.
- Historical Database Search was an ordinary input inside the fully regenerated page.
- Result: keyboard/focus briefly opened, then the input node was replaced by the next passive render.

V12.2 RENDER BOUNDARY
- Search input is marked data-rf-live-edit="database-search".
- RF.Views.Database.V122.shouldHoldRender() returns true only when:
  - Database is the active tab;
  - that exact search field owns document focus;
  - no RF.UI modal is open;
  - no action game is active;
  - no combat is active;
  - no explicit forced Codex render is in progress.
- Search typing updates the result list/counter/clear control in-place.
- Sector navigation uses an explicit allowed render.
- World time is not paused by this guard.
