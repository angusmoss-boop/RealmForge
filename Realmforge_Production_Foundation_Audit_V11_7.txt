REALMFORGE V11.7.0 — PRODUCTION FOUNDATION II / CANONICAL ARCHITECTURE AUDIT

PURPOSE
=======
V11.7.0 establishes the production source architecture that V12 will build on without attempting a high-risk all-at-once rewrite of the proven V11.5.3 gameplay implementation.

ARCHITECTURAL DECISION
======================
Realmforge now uses a strangler-style refactor:
1. The proven V11.5.3 behaviour is frozen behind a compatibility layer.
2. Clean canonical contracts exist for Core, Platform, Data, Systems and UI.
3. New V12 development targets those contracts instead of adding historical v12_x.js wrappers.
4. Existing systems can be reimplemented behind the same contracts one at a time, with regression testing, until the compatibility layer can be removed entirely.

This is intentionally safer than manually rewriting a mature 1.2 MB accumulated runtime in one release.

ACTIVE SHIPPED RUNTIME
======================
The browser now loads six JavaScript files:
- js/legacy/base/data.js
- js/legacy/base/state.js
- js/legacy/base/ui.js
- js/legacy/base/main.js
- js/legacy/compat_v1153.js
- js/dist/canonical_v11_7.js

The first five files are the frozen compatibility implementation. The sixth is a generated production bundle built from the readable canonical source modules.

COMPATIBILITY PROOF
===================
The four files under js/legacy/base are byte-identical to V11.6.1's proven data.js/state.js/ui.js/main.js files.
js/legacy/compat_v1153.js is byte-identical to V11.6.1's proven realmforge_runtime_v11_6_1.js.
No gameplay code was edited while moving it behind the legacy boundary.

NEW PRODUCTION RULES
====================
- New content definitions register through RF.Catalog.
- New schema migrations register through RF.Core.Migrations.
- New gameplay systems live under js/systems/.
- New platform/native behaviour lives under js/platform/.
- New interface ownership lives under js/ui/.
- Do not add new v12_x.js monkey-patch files around older global functions.
- Game version and save schema remain separate.
